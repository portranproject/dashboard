# 탐지 엔진 대시보드 샘플 — 목록과 만든 방법

2026-11-05 · 대시보드 담당에게 `04_분석/탐지엔진-설계/27_탐지엔진_1-4단계-대시보드-지표_명세서.md`와 함께 보내는 샘플 34개(경보 경로 32 · 상시 경로 2)의 목록이다. 대시보드 2차 답변서(11/04) R8에 답한다. 형식 설명은 `27_`.

## 만든 방법

- **지금 코드 출력이다.** `~/detection` `dev`(11/05, 1~4단계·결함 수정 M10·#100 반영)를 Release로 빌드한 `build-rel/detector`로 저장소 시험 데이터(`tests/data/`, 합성)를 `--replay`했다. 설정은 저장소 `config/detector.json` 기본값(증거 모드 `full`).
- **세션 이름만 바꿨다.** 시험 데이터는 모두 세션 `S1`(·`S2`)이라 파일끼리 `alert_id`가 겹친다(대시보드 11/04 지적). 그래서 재생 전에 입력 사본의 `session` 값만 샘플마다 겹치지 않는 기동 시각 모양(`20261105T…Z`)으로 바꿨다. 세션 이름을 되돌리면 32개 모두 원래 재생 출력과 바이트가 같음을 확인했다. 34개 사이에 같은 `alert_id`는 없다.
- **상시 경로 2개**는 입력 기록(`input_record.path`)을 켜고 재생한 뒤, **실제 전송기**(`tools/dashboard_sender.py --once`, `kpm2_interval_ms` 3000, `send_ue_evt` `false`)를 로컬 가짜 HTTPS 수집 서버에 붙여 받은 요청 본문을 받은 순서대로 이어 붙인 것이다 — 대시보드 `/ingest`가 받을 줄 그대로다. 받은 헤더: `Content-Type: application/x-ndjson`, `X-Env: sample`(샘플용 값 — 실제는 `p4`·`lab`), `User-Agent: ran-detect-sender/1`, `Authorization` 없음.
- 값은 합성 시험 데이터라 실측과 다르다(셀 1개, `kpm2`는 1단계 3종만, 시각 2026-10 근처).
